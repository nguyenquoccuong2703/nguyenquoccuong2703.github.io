Milestone and recurring value events for ROAS bidding

Two ways to send revenue signals to ad networks so value-based campaigns find better users.

Value-based campaigns, such as target ROAS on Google Ads, only work as well as the revenue signal you send back. For ad-monetized games, revenue arrives in many tiny amounts, so how you package it into events matters. Two event types cover most needs.

Milestone events: find the valuable users

A milestone event fires the first time a user reaches a threshold, for example watching 20 rewarded ads, completing level 50, or reaching a lifetime value of $5.

  1. Before the milestone, revenue is summed but nothing is sent.
  2. When the user reaches it, send one event with the total revenue so far, then reset the counter.
  3. After that, send an event every time this user generates revenue, with that revenue as the value.

Because users who reach the milestone are your most valuable, sending every bit of their revenue teaches the network exactly what a high-value user looks like, which improves lookalike targeting.

Recurring events: a steady signal for everyone

A recurring event fires every time a user accumulates a fixed amount, for example every $1 of revenue, every 5 sessions or every 10 levels.

  1. Revenue is summed since the last event.
  2. When the step is reached, send one event with the summed value and reset.
  3. Repeat at every step.

This covers all users, including small spenders, without flooding the network with thousands of tiny events.

Which one to use

GoalUse
Find spenders and heavy ad watchersMilestone
Deeper optimization and better lookalikesMilestone
Data that covers every userRecurring
A stable signal without event spamRecurring

Many games run both: milestones to track high-value users in depth and recurring events to track everyone broadly. Keep thresholds in remote config so UA and product can tune them without a new build, and make sure analytics knows which events are bidding signals so they do not distort other reports.
