Technical setup checklist for a new mobile game

Accounts, tools and permissions to prepare when a new game project starts.

Setting up a new game touches many tools and many people. A shared checklist with a clear owner for each step avoids missed keys, wrong permissions and last-minute surprises before launch.

1. Game identity

  • Decide which developer account will publish the game.
  • Choose the bundle ID or package name carefully. It cannot change after the first release.
  • Give the game an internal code and one central profile where every key and ID is stored.

2. Team workspace

  • Documentation space from the company template.
  • Task tracker project from a standard template so workflows match across games.
  • Shared storage for art and builds with a standard folder structure.
  • Code repository with branch protection.

3. Store and analytics

  • Firebase apps for Android and iOS, linked to Google Analytics and BigQuery export from day one.
  • Crash reporting turned on at the same time.
  • Google Play Console and App Store Connect apps, with permissions by role (release for product, store and feedback for UA).
  • Link the store to analytics once the game is live.
  • Facebook app ID for the SDK. It is separate from the ads account.

4. Attribution and monetization

  • MMP app created and permissions granted.
  • Mediation SDK key and ad unit IDs for all three formats (banner, interstitial, rewarded), checked before handing over to dev.
  • Other network app IDs as needed.

5. Dashboards and support

  • Cost and revenue dashboards connected after release.
  • Admin and customer support tools with project access.

Make it a habit

For every row, write down who is accountable, who does it, and what the output is. Reviewing the checklist at kickoff and again before soft launch catches most setup problems while they are still cheap to fix.
